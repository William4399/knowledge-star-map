# 知识星图 · 产品说明

> 一个把「我该学什么、我到底会不会、我能做什么」变成可见星空的软件工程学习地图。

---

## 一、这是什么

知识星图是一个面向计算机 / 软件工程专业学生的**可视化知识体系与能力验证工具**。

它把整个专业的知识拆成一颗颗星星，按领域聚成星云，用连线标出「先学什么、后学什么」。学生只有在通过客观挑战之后，星星才会被点亮；已点亮的星图会累积成一份可以对外展示的能力档案。

一句话概括：**把模糊的「我好像学过」，变成可以点亮、可以验证、可以展示的星图。**

产品由三条主线构成：

1. **告诉你先学什么**：基于前置依赖与目标方向，实时计算「现在就能挑战」的下一批星星
2. **验证你是否掌握**：每个知识点配客观挑战题，通过才点亮，失败给出具体扣分项
3. **把能力翻译成机会**：把已点亮星图转成能力雷达图、对口岗位与可参加的比赛

---

## 二、要解决的问题

### 1. 学完课内之后，不知道往哪走

大学课程给的是「课程表」，不是「知识地图」。学生知道这学期要学数据结构，但不知道学完数据结构能通向什么，也不知道操作系统和网络谁该先学、后端和算法哪条路更适合自己。

现有方案（roadmap.sh、各类学习路线图）都是**树状清单**，只能表示「包含」，不能表示「依赖」，也没有任何验证机制。

### 2. 「我掌握了」是一句无法验证的话

简历上写「熟练掌握 Java」没有任何成本。学生自己也常常高估或低估自己——看懂了视频就以为会了，做不出题又以为自己一无是处。

知识星图用**挑战题 + 关键词判分**把「掌握」变成可验证的事件，并把自评与实证分开记录。

### 3. 能力和机会之间缺少翻译层

学生不知道自己现在这套技能组合，能打什么比赛、能投什么岗位、离校招要求还差哪几颗星。

## 三、目标用户与典型场景

| 用户 | 场景 |
|---|---|
| 大一大二学生 | 刚学完 C 语言，想知道下一步该点什么 |
| 大三大四学生 | 准备校招，想知道自己离后端岗还差哪些能力 |
| 跨专业自学者 | 没有培养方案，需要一条有依据的自学路径 |
| 参赛 / 做项目的人 | 想知道做这个方向需要补齐哪些前置知识 |

典型使用流程：

1. 首次打开完成新手引导：选择专业年级、勾选自评已掌握的知识、做 6 道摸底题、选择目标方向
2. 在星图上看到推荐高亮的下一批星星，点击查看详情并发起挑战
3. 答题通过后星星点亮，状态栏与路径页同步更新
4. 在「成长路径」查看当前方向下的可挑战节点与能力清单
5. 在「我的」查看能力雷达图、称号、对口岗位与比赛匹配，可导出 / 导入存档

## 四、核心概念

| 概念 | 含义 |
|---|---|
| **星系（Galaxy）** | 一个知识大类，对应国际课程体系的一个知识域。用颜色和星云区分，不画边框 |
| **星星（Node）** | 一个可学习、可验证的知识点。例如「Python」「索引原理」「事务与并发控制」 |
| **星线（Edge）** | 知识点之间的有向关系。分「必修前置」和「建议先修」两种 |
| **点亮（Lit）** | 通过该知识点的挑战后，星星变亮并记录在案 |
| **自评待验证（Claimed）** | 新手引导中自评「已掌握」但尚未通过挑战，用细环标记，不计入点亮 |
| **重要度（Importance）** | 星星的大小。定义为一个节点被多少下游节点依赖——越底层越重要，越大 |
| **难度（Complexity）** | 学习门槛，范围为 1–5。只影响详情卡里的难度条，不影响星星大小 |
| **任一即可（any_of）** | 某些节点允许「多选一」的前置，例如数据结构要求掌握任意一门编程语言 |

### 重要度和难度为什么要分开

大多数知识图谱把「难」和「重要」混为一谈，导致最该先学的基础知识被画成小点。

本产品的定义：

- **重要度 = 下游依赖数量（图的出度）**：C 语言、Python、数组与链表、操作系统基础、Git 之所以最大，是因为不学它们，后面几十颗星都点不亮
- **难度 = 认知层级**：从「知道概念」到「能实现」再到「懂原理」

这样画出来的星图，大星星是「地基」，小星星是「选修」，视觉大小本身就传达了学习优先级。

## 五、知识体系

当前版本共 **11 个星系、52 颗星、71 条依赖关系**，覆盖软件工程主干。星系划分参考 ACM/IEEE-CS/AAAI **CS2023** 课程体系与 **SWEBOK v4** 软件工程知识体系。

| 星系 | 对应知识域 | 星星数 | 内容举例 |
|---|---|---|---|
| 编程语言 | SDF / FPL | 5 | C、C++、Java、Python、JavaScript |
| 数据结构与算法 | AL | 8 | 复杂度分析、数组与链表、树、图、哈希表、排序、动态规划 |
| 计算机系统 | AR / OS | 5 | 计算机组成原理、操作系统、进程与线程、内存管理 |
| 网络与 Web | NC | 4 | 网络基础、HTTP、前端框架、浏览器与渲染 |
| 数据与存储 | DM | 5 | 关系型数据库、SQL、索引原理、事务与并发、NoSQL 与缓存 |
| 软件工程 | SWEBOK 需求 / 测试 | 3 | 需求分析、软件测试、软件架构 |
| 工程实践 | SWEBOK CM | 5 | Git、单元测试、CI/CD、调试、技术文档 |
| 后端与架构 | SWEBOK 架构 | 5 | 后端框架、API 设计、系统设计、微服务、分布式 |
| 安全基础 | SEC | 3 | Web 安全、密码学、认证与授权 |
| 数学基础 | MSF | 3 | 线性代数、概率统计、离散数学 |
| 人工智能 | AI | 6 | 数据处理、机器学习、深度学习、大模型应用、RAG、模型评估 |

### 依赖规则

1. **必修前置（prerequisite）**：必须全部点亮，才能挑战当前节点
2. **建议先修（suggested）**：不阻断挑战，只作为学习顺序提示
3. **任一即可（any_of）**：节点上的可选前置列表，满足任意一个即可
4. **无环约束**：所有必修关系必须构成有向无环图，由 `verify_graph.py` 校验

三类典型路径：

```
编程语言 → 数据结构与算法 → 计算机系统 → 网络与 Web → 数据与存储 → 后端与架构
Python → 数据处理与分析 → 机器学习 → 深度学习 → 大模型应用 → 检索增强
Python / 线性代数 / 概率统计 → 机器学习 → 模型评估与实验
```

## 七、挑战与判分规则

- **题型**：`choice` 单选、`short` 简答
- **选择题**：选项与答案完全一致即得分
- **简答题**：对答案文本做关键词匹配，命中数 ≥ `minHits` 视为该题达标；未达标时按 `min(0.6, 命中数 / 关键词数 × 0.6)` 给部分分
- **总分**：各题得分平均值 × 100
- **通过条件**：**总分 ≥ 60 且所有简答题达标**；通过后点亮星星并记录 `best` 最好成绩
- **记录**：每次挑战累计 `attempts` 与 `best`，详情卡与个人主页可见
- **错题**：答错的题目记录题型、你的选择或缺失关键词与累计错误次数；下次答对即移除，通过整颗星后清空该节点错题

> 说明：判分在浏览器本地完成，题库与答案随静态资源下发，仅用于学习自测，不具备防作弊能力。

## 八、推荐与匹配算法

### 1. 路径推荐（成长路径 / 星图高亮）

`buildPlan()` 对每个未点亮节点计算优先级：

- **前置是否满足**：必修前置全部点亮才进入「现在就能挑战」，否则进入「接下来会解锁」
- **方向权重**：目标方向对 11 个星系配置权重，权重越高越靠前
- **重要度 / 难度**：重要度高、难度低的优先
- **解锁潜力**：点亮后能解锁多少下游节点
- **必修加分**：属于目标方向必修清单的节点额外加权

输出 `ready` / `upcoming` / `progress` 三组，星图高亮 `ready` 前 6 个。

### 2. 按周学习计划

在同样的评分规则上做一次「模拟解锁」：

1. 从未点亮节点出发，每轮在当前可挑战集合中取分数最高的节点，加入序列并视为已点亮，继续下一轮
2. 用节点难度换算学习时长（难度 × 2.5 小时），按每周可投入时长（8 / 12 / 16 / 20 小时）切分成周
3. 计划保存方向、周期、每周投入、开始日期、生成时间与任务列表；完成状态由实时点亮结果推导，不额外存一份「勾选」
4. 切换周期或每周投入时按新节奏重排任务；修改开始日期只影响周次显示与日历，不改变任务内容
5. 点击「重新规划」会从今天开始新周期，并按当前进度重新排序；点亮结果变化只更新完成状态，不打乱既定安排
6. 「导出日历」为每个有任务的周生成一个全天日程（`.ics`），描述中包含方向、预计投入与任务清单，可直接导入系统日历

### 3. 岗位与比赛匹配（个人主页）

- **方向能力覆盖**：必修节点覆盖比例（权重 65%）
- **星系掌握度**：该方向相关星系的平均掌握度（权重 35%）
- 取匹配度最高的 3 个方向，展示对口岗位与建议参加的比赛

> 岗位与比赛数据为人工整理的参考清单，不代表任何招聘方的实际要求。

## 九、数据结构

数据分为三份，均位于仓库内，由前端 `fetch` 读取。

### 1. `star-data.json` —— 知识图谱

```json
{
  "galaxies": [{ "id": "ai", "name": "人工智能", "ka": "AI", "color": "#E879F9", "ax": -590, "ay": 192 }],
  "nodes": [{
    "id": "ai_ml", "name": "机器学习入门", "galaxy": "ai",
    "importance": 4, "complexity": 4, "core": true,
    "description": "监督/无监督学习、损失函数、过拟合与交叉验证",
    "resources": [{ "type": "book", "title": "《机器学习》周志华" }],
    "any_of": ["python"], "ai_generated": false
  }],
  "edges": [{ "from": "ai_data", "to": "ai_ml", "type": "suggested", "weight": 0.5 }]
}
```

| 字段 | 说明 |
|---|---|
| `importance` | 1–5，决定星星半径：`2.6 + importance × 1.7` |
| `complexity` | 1–5，仅用于详情卡难度条 |
| `core` | 是否为该方向核心节点 |
| `resources` | 学习资源列表，可含书籍、课程、文档链接 |
| `any_of` | 可选前置，满足任意一个即可 |
| `type` | `prerequisite` 必修前置 / `suggested` 建议先修 |
| `ax` / `ay` | 星系在画布上的引力中心 |

### 2. `data/questions.json` —— 挑战题库

```json
{
  "meta": { "pass_threshold": 60 },
  "questions": {
    "eng_git": [
      {
        "id": "q_eng_git_1", "type": "choice",
        "stem": "……", "options": ["…", "…", "…", "…"], "answer": 0,
        "explain": "……"
      },
      {
        "id": "q_eng_git_2", "type": "short",
        "stem": "……", "keywords": ["fetch", "rebase", "冲突"], "minHits": 2,
        "reference": "……", "explain": "……"
      }
    ]
  }
}
```

共 104 题（85 选择 + 19 简答），覆盖全部 52 个知识点，每个知识点固定 2 题；简答题按关键词命中数判分。

### 3. `data/roles.json` —— 方向 / 岗位 / 比赛

```json
{
  "roles": [{
    "id": "backend", "name": "后端开发", "short": "后端",
    "tagline": "……", "description": "……",
    "galaxyWeights": { "lang": 0.8, "backend": 1.0, "data": 0.9 },
    "required": ["c", "python", "db_sql"],
    "anyOfGroups": [{ "name": "至少一门语言", "ids": ["java", "python", "c"] }],
    "jobs": [{ "title": "后端开发工程师", "keywords": ["Java", "MySQL"] }],
    "competitions": [{ "name": "……", "note": "……" }],
    "skills": ["……"]
  }]
}
```

共 6 个方向：后端开发、前端开发、AI 应用、安全工程、基础设施、算法与竞赛。

### 扩展方式

新增星系：在 `galaxies` 中追加一项，给它一个 `ax` / `ay` 坐标。

新增星星：在 `nodes` 中追加节点，`galaxy` 指向已有星系，在 `edges` 中补依赖，并在 `data/questions.json` 中补题；若属于某方向，同步更新 `data/roles.json`。

新增后必须运行校验：

```bash
python verify_graph.py
```

## 十、技术架构

```
┌──────────────────────────────────────────────────┐
│ index.html（空壳：四个视图容器 + 导航 + 弹窗根）   │
└───────────────┬──────────────────────────────────┘
                │ ES Module
   ┌────────────▼─────────────┐
   │ js/app.js  启动 / 路由 /   │
   │ 详情卡 / 状态同步          │
   └───┬────┬────┬────┬────┬──┘
       │    │    │    │    │
   graph  path  plan profile sharecard challenge onboarding ics
       │    │    │    │    │
       └────┴────┴────┴────┴──┐
                    js/data.js │  js/store.js  js/util.js
                     (加载/索引) │ (localStorage) (工具/弹窗)
                              │
        star-data.json · data/questions.json · data/roles.json
```

- **纯前端**，无后端与数据库，静态服务器即可运行
- 图形渲染基于 `force-graph` 的 Canvas 接口，自行绘制节点、连线、星云
- 无构建步骤、无框架依赖，浏览器原生 ES Module
- 状态集中在 `js/store.js`，通过订阅机制驱动各视图刷新
- `sw.js` 采用网络优先 + 缓存兜底：在线时始终取最新资源并更新缓存，断网时回退到缓存，保证开发与使用都不会读到旧文件
- `manifest.json` 提供安装能力、主题色与 `#plan` / `#profile` 快捷入口；图标按 192 / 512 / 180 三种尺寸生成

## 十五、视觉设计说明

整体方向是「真实星空」，而不是「科技感仪表盘」。

| 元素 | 设计 |
|---|---|
| 背景 | 真实星云照片压暗至 40% 亮度、65% 饱和度，中心叠暗便于阅读；另有约 180 颗低亮度闪烁星点 |
| 星星 | 三层结构：大范围柔光 + 两道拉长弧光 + 白热星核；每颗星闪烁相位独立 |
| 星系 | 用半透明径向色雾区分大类，取星系平均位置与散布半径，不画边框、不画虚线圆 |
| 星线 | 0.6–1.0px 细线，底透明度极低；叠加流动光点 |
| 亮度层级 | 已点亮亮度约为未点亮的 2.7 倍；连线亮度低于星星，保证主次分明 |
| 推荐标识 | 推荐节点外圈呼吸光环，与「已点亮」「待验证」的环形态区分 |
| 文字 | 星星名随缩放淡入，星系名随缩放淡出；文字带暗色阴影保证可读 |
| 动效 | 全部为 canvas 实时绘制，遵循系统减少动态效果设置 |

## 十六、已知限制

诚实说明当前版本的问题，避免演示时被问倒：

1. **判分基于关键词**：简答题不理解语义，同义表达可能漏判；题库随静态资源下发，无防作弊能力
2. **无账号体系**：存档只在当前浏览器，换设备需手动导出 / 导入
3. **岗位数据为参考**：`roles.json` 中的岗位与比赛为人工整理，非实时招聘信息
4. **节点覆盖有限**：52 颗星覆盖主干，嵌入式、图形学、测试开发等细分方向尚未展开
5. **布局为手工锚点**：星系中心坐标为人工设定，节点大幅增加后需改为自动聚类
6. **题目深度有限**：每个知识点固定 2 题（1 选择 + 1 简答或 2 选择），仍以记忆与关键词判断为主，缺少代码题与开放题
7. **错题记录为最新状态**：每题只保留最近一次错误的选择 / 缺失关键词与累计错误次数，不保存历次作答原文
8. **分享卡为本地图片**：能力档案卡由 Canvas 在本地绘制，不包含在线主页链接或二维码；「复制文字摘要」依赖浏览器剪贴板权限
9. **无服务端**：无法做在线排行榜、跨设备同步、题目动态更新
10. **日历导出为单向**：`.ics` 为全天事件，不含提醒与完成状态回写；修改计划后需重新导出
11. **热力图只统计首次点亮**：活跃度来自首次点亮时间，不包含挑战失败、复习等未点亮事件
12. **离线依赖首次联网**：清除站点数据或从未联网打开过时无法离线使用；安装入口是否出现取决于浏览器支持，Safari 需通过分享菜单「添加到主屏幕」
